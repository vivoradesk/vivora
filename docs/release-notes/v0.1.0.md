# Vivora 0.1.0

The first public release. The streaming pipeline has been in daily use for
months; this is the first time it has been packaged for people who did not
write it. Expect rough edges in the desktop app before you expect them in the
stream.

**Windows and Linux builds are published here.** macOS builds from source and
works, but signed and notarised downloads need an Apple Developer account and
are the first item on the 0.1.1 list.

## What it does

Streams a desktop over a custom UDP protocol with a GPU-to-GPU video path:
DXGI / PipeWire / ScreenCaptureKit into NVENC, AMD AMF, Intel QSV, VAAPI or
VideoToolbox, decoded on the other side into a hardware surface and presented
without ever touching system memory. H.264 and HEVC, negotiated per connection
from what the client can actually decode. HDR passthrough on Windows and macOS.
Reed-Solomon FEC with burst interleaving and targeted NACK recovery, adaptive
bitrate and framerate, Opus audio with an adaptive jitter buffer, text clipboard
sync, multi-monitor selection.

Everything is end-to-end encrypted with `Noise_IK_25519_ChaChaPoly_BLAKE2b`. A
host's Curve25519 public key is its identity, pinned on first use. The
rendezvous server and the relay are in this repository under AGPL-3.0 and you
can run both yourself.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list and
[STATUS.md](../../STATUS.md) for the honest per-platform state.

## Windows

The installer puts Vivora in `%LOCALAPPDATA%\Programs\Vivora` for the current
user, so it never asks for administrator rights. Uninstall from
Settings → Apps; your settings in `%APPDATA%\Vivora` survive.

**Windows will warn you about an unrecognised app.** The binaries are not
code-signed yet — a certificate that Windows trusts requires a hardware token
and an annual fee, and 0.1 ships without one. SmartScreen shows *"Windows
protected your PC"* with the *Run* button hidden behind **More info**. Check
the SHA-256 against `SHA256SUMS.txt` first; that is a stronger guarantee than
a signature you cannot inspect anyway.

## Linux

```sh
chmod +x Vivora-0.1.0-linux-x64.AppImage
./Vivora-0.1.0-linux-x64.AppImage
```

Requirements:

- **glibc 2.31 or newer** — Ubuntu 20.04+, Debian 11+, RHEL/Rocky/Alma 9,
  Fedora 32+, and everything more recent.
- **`libpipewire-0.3`** on the system if you want to *share* your screen. It is
  deliberately not bundled: the library loads plugins from the host and talks
  to the local PipeWire daemon, so a bundled copy would fail to connect. Any
  desktop with a working `xdg-desktop-portal` already has it.
- If the AppImage refuses to start with a **libfuse** error, run it with
  `--appimage-extract-and-run`. The bundled runtime handles fuse3 systems, but
  containers and some minimal installs have neither.

**To let a remote user control this machine**, Vivora needs write access to
`/dev/uinput`, which is root-only by default. Without it the video stream works
perfectly and input silently does nothing:

```sh
sudo cp 60-vivora-uinput.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo modprobe uinput
sudo usermod -aG input "$USER"      # then log out and back in
```

The rule ships in `packaging/linux/` in the source tree.

## Self-hosting

`vivora-servers-0.1.0-linux-x64.tar.gz` contains both server binaries, hardened
systemd units and an `install.sh` that puts them in place. The rendezvous
server needs UDP 7000 and moves kilobytes per session; the relay needs UDP 7100
and carries the full stream, so size its bandwidth accordingly.

Point clients at yours in Settings, or with `--rendezvous host:port` and
`--relay host:port`.

## Known limitations

- No file transfer, no gamepad forwarding, no mobile clients.
- No software encoder fallback: a machine with no usable GPU encoder cannot
  share its screen.
- Linux hosts advertise their monitors but cannot switch between them yet.
- Linux HDR capture is an 8-bit pipeline.
- Linux relative-mouse capture is X11 only — Wayland forbids the pointer warp
  it needs.
- The input channel is fire-and-forget. A lost key-up event on a bad link can
  leave a modifier stuck; click into the stream window again to clear it.

## Reporting problems

Attach `vivora.log` from `%LOCALAPPDATA%\Vivora\Vivora\` (Windows) or
`~/.local/share/Vivora/` (Linux). The previous session is kept next to it as
`vivora.log.1`, which is usually the one worth sending after a crash. For a
verbose run, start with `VIVORA_LOG_LEVEL=debug`.

For stream-quality reports, press **F9** in the stream window and include what
the diagnostics overlay shows.

Security issues go to security@vivora.dev, not the issue tracker — see
[SECURITY.md](../../SECURITY.md).
