# Vivora 0.1.1

**macOS gets a download**, and the Windows builds are now signed. The rest is
host fixes found in daily use since 0.1.0, the most important being that a
Windows host now survives a GPU driver reset.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list and
[STATUS.md](../../STATUS.md) for the per-platform state.

## What's new

- **macOS download.** A universal `.dmg` for Apple silicon and Intel Macs,
  signed with a Developer ID certificate and notarised by Apple, so it opens
  without a Gatekeeper warning. Requires macOS 14 or newer.
- **Signed Windows builds.** `vivora.exe` and the installer carry a code
  signature with a timestamp, so Windows names the publisher instead of
  showing "Unknown publisher".
- **GPU driver reset recovery (Windows host).** After a driver reset — a crash
  and restart of the graphics driver, a driver update, some games and GPU tools
  trigger one — the host used to refuse every connection until it was
  restarted, and a reset during a session crashed it on AMD GPUs. It now
  rebuilds its capture and encoder and the stream carries on by itself.
- **Monitor hot-plug.** Plugging a display in or out updates the monitor list
  on connected clients, and moving a session onto an HDR display switches the
  codec instead of sending a wrongly coloured picture.
- **macOS HDR.** The macOS viewer presents HDR streams from a Windows host with
  correct colours.
- **Relay fallback** no longer fails to connect, which hit Linux viewers most.
- **Pro license** expiry and renewal are picked up while the app is running.

## Windows

The installer puts Vivora in `%LOCALAPPDATA%\Programs\Vivora` for the current
user and never asks for administrator rights. The portable zip is the same
signed binary with no installer. Installing over 0.1.0 keeps your settings.

The certificate is new, so **SmartScreen may still show "Windows protected your
PC"** for a while: its reputation builds up with downloads, not with the
signature alone. The dialog now names the publisher; choose **More info → Run
anyway**.

**Windows running as administrator.** Windows does not let an ordinary program
send keyboard and mouse input to a program running as administrator. While an
elevated window has focus — an administrator terminal, Task Manager, an
installer — remote input is ignored and the remote cursor seems stuck; click
into any other window and it works again. If you need to control elevated
windows, start Vivora on the host with *Run as administrator*. UAC prompts and
the lock screen are out of reach either way for now; running the host as a
system service, which fixes all of this, is planned.

## macOS

Open the `.dmg` and drag Vivora to Applications. On first use macOS asks for
two permissions, both required to share this Mac:

- **Screen Recording** — to capture the screen.
- **Accessibility** — to let the remote side use the keyboard and mouse.
  Without it the picture works and input is silently dropped.

Grant them in System Settings → Privacy & Security, then quit and reopen
Vivora. Viewing another machine from a Mac needs neither. The grants survive
updates to later signed versions.

## Linux

Unchanged from 0.1.0:

```sh
chmod +x Vivora-0.1.1-linux-x64.AppImage
./Vivora-0.1.1-linux-x64.AppImage
```

glibc 2.30 or newer, `libpipewire-0.3` to share the screen, and write access to
`/dev/uinput` to accept remote input — see the
[0.1.0 notes](v0.1.0.md#linux) for the details and the udev rule.

## Compatibility

0.1.1 and 0.1.0 connect to each other in both directions. A 0.1.0 viewer
ignores the new codec-change message, so it can still show a broken picture if
a 0.1.1 host switches codec mid-session; update both sides when you can.

## Known limitations

- No file transfer, no gamepad forwarding, no mobile clients.
- No software encoder fallback: a machine with no usable GPU encoder cannot
  share its screen.
- Windows: no input into administrator windows unless Vivora runs as
  administrator; no access to UAC prompts or the lock screen (see above).
- macOS: no start at login yet.
- Linux hosts advertise their monitors but cannot switch between them yet;
  Linux HDR is 8-bit; relative-mouse capture is X11 only.
- The input channel is fire-and-forget. A lost key-up on a bad link can leave a
  modifier stuck; click into the stream window again to clear it.

## Reporting problems

Attach `vivora.log` from `%LOCALAPPDATA%\Vivora\Vivora\` (Windows),
`~/Library/Application Support/Vivora/Vivora/` (macOS) or
`~/.local/share/Vivora/Vivora/` (Linux). The previous session is kept next to
it as `vivora.log.1`. For stream-quality reports, press **F9** in the stream
window and include what the diagnostics overlay shows.

Security issues go to security@vivora.dev, not the issue tracker — see
[SECURITY.md](../../SECURITY.md).
